# Agents & Providers — Models as Citizens

*How an LLM (or a decision model) joins a cognitive ecology without
becoming its monarch.*

## The constitutional arrangement

```
        proposes (JSON, validated, fail-soft)
LLM ────────────────────────────────────────────► ScriptEcology
                                                    │ bids
                                                    ▼
 WHY tree ──(what may exist)──► AttentionMarket ──(what runs)──► Executive
```

The model never executes anything. It proposes small JSON objects that
parameterize scripts drawn from a **fixed action library** — code the
organism's author wrote and audited. The library is the safety boundary:
no `eval`, no generated code, no tool surface beyond typed actions.

If the model emits garbage, proposals are dropped silently (fail-soft)
and the agent's *accept-rate* EMA decays, which lowers its attention
bid. An LLM that proposes junk eventually loses the market's ear — the
same economics that governs a foraging script.

## Providers

| Class | Endpoint | Config |
|---|---|---|
| `OpenAICompatProvider.from_env("DEEPINFRA")` | DeepInfra (default model `tencent/Hy4-preview`) | `DEEPINFRA_API_KEY`, `DEEPINFRA_BASE_URL`, `DEEPINFRA_MODEL`, `DEEPINFRA_CACHE_KEY` |
| `OpenAICompatProvider.from_env("TYPESAFE")` | any OpenAI-compatible decision endpoint (default OpenRouter) | `TYPESAFE_API_KEY`, `TYPESAFE_BASE_URL`, `TYPESAFE_MODEL` |
| `MockProvider()` | none — deterministic, keyless, simulates caching | — |

Rules baked into the provider layer: **keys come from environment
variables only** (constructors raise on empty keys; nothing is ever
logged); retries with backoff on 429/5xx; stdlib `urllib` so the kernel
stays dependency-free.

## The caching strategy (and why it is a first-class concern)

Providers cache the **longest identical prefix** of your prompt. On
DeepInfra, `tencent/Hy4-preview` prices (USD per 1M tokens, checked
2026-10-31):

| Input (fresh) | Input (cached) | Output |
|---|---|---|
| $0.834 | **$0.042** | $2.501 |

Cached input is ~**20× cheaper** than fresh input, with automatic prefix
caching and an optional session-scoped `prompt_cache_key`. That changes
how you should build agents: **the shape of your prompt is a cost
decision.**

`StablePrefixSession` (agents/providers.py) enforces the discipline:

- the **stable prefix** (system prompt) is frozen for the session:
  identity introspect + action library + output contract;
- everything volatile (tensions, world digest, recent events, the ask)
  goes in the **user message**, *after* the prefix;
- every call journals tokens, `cached_tokens`, and hashes — savings are
  measured, not assumed;
- the prefix changes only via `set_prefix(reason)`, which is counted.

### The arithmetic (6,000-token prefix, 100 iterations)

| | Uncached | Cached |
|---|---|---|
| Prefix cost / iteration | 6,000/1M × $0.834 = $0.005004 | 6,000/1M × $0.042 = $0.000252 |
| **Per-iteration saving** | — | **$0.004752 (95%)** |
| **100 iterations** | $0.50 | $0.025 |

Add the non-prefix payload (say 4,000 fresh tokens + 800 output per
iteration) and the loop totals drop from ~$1.03 to ~$0.56 — the prefix
discipline alone halves the cost, and it compounds with context size: a
50k-token repo-context prefix takes the same loop from ~$4.2 to ~$0.4.
(Worked through in `experiments/dogfood/2026-10-31-hy4-comprehension-and-cache.md`,
which was itself generated by Hy4-preview during dogfooding.)

### What never goes in a prefix

Anything with a timestamp or tick; tension levels; world digests; WHY
*states* (statements are fine — they're stable); anything you expect to
edit while iterating. If you must change the prefix, do it between
sessions and let `set_prefix()` count the bust.

### Identity drift is scheduled, not ad hoc

`Identity.introspect()` is memoized: byte-identical for the whole session
no matter how many commitments accumulate. New commitments surface only
at `Identity.drift()` — typically between sessions. Slow identity is not
a limitation; it is the mechanism that makes long-lived cheap agents
possible. (Full template: `src/cognitive_ecology/agents/stable_prefix.md`.)

## Wiring an LLM agent (the whole ceremony)

```python
from cognitive_ecology import Identity, Runtime
from cognitive_ecology.agents import (
    ACTION_LIBRARY_DOC, LLMAgent, OpenAICompatProvider, StablePrefixSession,
)

rt = Runtime(seed=3, top_k=2)
rt.declare_why("learn things and persist", node_id="why:root")
rt.tensions.add("curiosity", growth=0.05)
rt.identity = Identity("scout", why=rt.why)

prefix = (
    "You are scout, a citizen of a cognitive-ecology organism.\n\n"
    "## Action library\n" + ACTION_LIBRARY_DOC + "\n\n"
    "## Output contract\n"
    'Reply with a JSON array of proposals: {"name", "action", "args",\n'
    ' "relieves", "focus", "when_hint"}.'
)
session = StablePrefixSession(
    OpenAICompatProvider.from_env("DEEPINFRA"),  # or MockProvider()
    prefix, journal_path="experiments/dogfood/journal.jsonl", label="scout",
)
rt.register(LLMAgent("scout", "why:root", session, every=5))
rt.run(100)
print(session.stats())   # calls, cache_hit_rate, est_saved_usd
```

## The action library (the safety boundary)

| Action | Args | Effect |
|---|---|---|
| `observe` | `focus: [ids]` | mark graph nodes as seen (create if absent) |
| `note` | `text` | write a note node + journal signal |
| `search` | `topic`, `link_to: [ids]` | chart a topic node (one-shot: re-charting fails honestly) |
| `message` | `target`, `text` | emit a SIGNAL to another actor |
| `rest` | `tension`, `amount` | relieve a tension |

`when_hint` triggers come from a tiny safe DSL: `"always"` |
`"tension_above:<name>:<x>"` | `"every:<n>"`. Extending the library
means writing one audited function — the model gains a new verb, never
a new kind of power.
